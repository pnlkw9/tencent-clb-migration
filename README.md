## 先弄明白腾讯云负载均衡（CLB）负责什么

CLB 负责把访问流量自动分配到多台后端服务器上，用来扩展服务能力、消除单点故障。官方文档给出的规格是支持亿级连接和千万级并发。

它本身不处理请求，只做转发。所以在建 CLB 之前，先要有能处理请求的云服务器（CVM），并在上面部署好 Web 服务，Apache、Nginx、IIS 都行。后端服务没跑起来，CLB 配得再顺，访问结果也只有超时。

一个省事的顺序是：先确认后端服务能正常响应，再回来建 CLB。这样出问题时，排查范围会小很多。

## 第一步：创建负载均衡实例

创建时最需要确认的是地域和网络。地域要和后端 CVM 一致，因为绑定后端服务器时，控制台只列出同地域、同 VPC、相同网络环境、未被隔离、未过期、带宽峰值不为 0 的 CVM。地域选错，后面绑定环节直接没得选。

网络选 VPC。CLB 的启停功能也只在 VPC 网络下支持，基础网络不支持。

如果你在控制台买不了传统型，原因很简单：2021 年 10 月 20 日起它就停止新购了。新用户默认创建的就是普通负载均衡实例。

实例建好后会出现在实例列表里。计费方式和带宽按业务预估选，不确定就先用低配把流程跑通。

## 第二步：创建监听器

监听器决定 CLB 用什么协议、哪个端口接收流量，以及把流量转发到后端的哪个端口。

协议按业务选：

- TCP、UDP、TCP SSL 属于四层监听，按端口转发；
- HTTP、HTTPS 属于七层监听，可以按域名和 URL 路径分发。

业务是 HTTP/HTTPS，且需要按域名或路径把请求分给不同后端组，选七层；协议本身不是 HTTP，或者只需要端口转发，选四层。

以一个普通 HTTP 服务为例，典型配置是：监听协议端口 HTTP:80，后端端口 80，均衡方式加权轮询，开启健康检查。会话保持看情况，后端是无状态服务的话，开不开影响不大；需要把同一用户的请求固定在同一台服务器上，再开启。

## 第三步：绑定后端服务器

绑定入口在监听器管理里。HTTP/HTTPS 监听器要逐层展开：监听器、域名、URL 路径，然后点绑定；TCP/UDP/TCP SSL 监听器直接选中监听器点绑定。

绑定弹窗里能选的 CVM 有硬性范围：同地域、同 VPC、相同网络环境、未被隔离、未过期、带宽峰值不为 0，缺一个都看不到。要跨地域或跨 VPC 绑定，得用跨地域绑定 2.0。

绑定多个后端服务器时，CLB 按 Hash 算法转发流量。权重决定请求的相对分配量，默认 10，可设 0 到 100，权重越大分到的请求越多。权重设成 0 的服务器不再接受新请求，这个特性可以拿来做优雅下线：先把权重调到 0，等存量请求处理完再解绑，比直接解绑温和。

直接解绑会立即停止转发，但不会影响 CVM 的生命周期，之后还能再加回来。

如果 CLB 关联了弹性伸缩组，组里的 CVM 会自动加入后端列表；从伸缩组移除实例时，也会自动从后端删除。用伸缩组的场景不需要手动维护后端列表。

## 第四步：配置安全组

配置安全组前，先决定用哪种模式：开启还是关闭安全组默认放通。这决定了流量要过几道检查，以及健康检查要不要额外放通 VIP。

开启默认放通后，来自 CLB 的流量只需通过 CLB 的安全组，CVM 会默认放通来自 CLB 的流量，CVM 不必对外暴露端口。来自公网 IP（含普通公网 IP 和 EIP）的流量，仍然要过 CVM 安全组。要拒绝某个 Client IP，必须在 CLB 的安全组里拒绝，在 CVM 安全组里拒绝对来自 CLB 的流量不生效。

关闭默认放通后，业务流量要同时通过 CLB 安全组和 CVM 安全组两道检查，拒绝某个 IP 可以在这两边任意一处配置。但健康检查要额外处理：公网 CLB 需要在 CVM 安全组上放通 CLB 的 VIP，因为 CLB 用 VIP 探测 CVM 的健康状态；VPC 网络的内网 CLB 同理；基础网络的内网 CLB 默认放通健康检查 IP，不用配。

默认状态因实例而异：IPv4 CLB 和 NAT64 的安全组默认放通默认关闭，可以在控制台开关；IPv6 CLB 的默认放通默认开启，而且无法关闭。配 IPv6 业务时要留意这个差异。

数量上有两个上限：每个 CLB 最多绑定 5 个安全组；单个安全组的规则上限是 512 条，入站规则、出站规则和后端参数模板展开后的规则总数都算在内。不够用要走配额管理申请。

还有几类不支持的情况：传统型内网 CLB 和基础网络的内网 CLB 不支持绑定安全组；跨地域绑定 2.0 和混合云部署不支持默认放通，得在后端服务的安全组上放通 Client IP 和服务端口；安全组默认放通只对本 VPC 内弹性网卡或 CVM 类型的后端服务生效，绑定 CDB 这类 PaaS 服务时不生效。

内网 CLB 绑定 EIP 的场景还有一个时间分界：2024 年 8 月 1 日之后创建的 CLB，安全组对来自 EIP 和内网 CLB 的流量都生效；在这之前创建的实例，安全组对来自 EIP 的流量不生效，需要提工单处理。

一个常见的公网 CLB 配置示例：入站规则放通 0.0.0.0/0 的 80 端口，拒绝其他端口，监听器 HTTP:80 转发到 CVM 的 8080 端口。安全组规则从上往下依次匹配，允许规则通过后其余默认拒绝，注意配置顺序。👉 [查看腾讯云负载均衡的开通入口与安全组配置指引](https://bit.ly/yunhuodong)

## 第五步：验证服务与启停实例

配完先看健康检查状态。展开监听器，后端 CVM 显示“健康”，说明 CLB 能正常把请求转给它；一直异常，回头查两件事：CVM 上的服务端口通不通，安全组有没有放通 CLB 的 VIP（关闭默认放通的场景）。

状态正常后，在浏览器访问 `http://VIP:80`，刷新几次。监听器是加权轮询、两台 CVM 权重都是 10 的话，请求会轮流落到不同服务器上。

暂时不用的实例可以停止。停止后 CLB 不再接收和转发流量，所有监听器随之停止，客户端连 Telnet 连接都建不了。启动实例时所有监听器一起恢复。

有个细节值得记住：停止实例后单独启动某一个监听器，实例会转为启动状态，但其他监听器仍然保持停止。只想起一个监听器的时候，别被实例状态迷惑。

启停的限制：传统型不支持；只有 VPC 网络支持，基础网络不支持；IPv6 NAT64 也不支持。

想让用户用域名访问，加一条 A 记录解析到 CLB 即可：记录类型 A，主机记录按需填，记录值关联刚创建的 CLB 实例，TTL 默认 600 秒。解析生效需要一点时间。

## 常见问题

**传统型负载均衡还能买吗？**

不能。2021 年 10 月 20 日起停止新购。新用户默认创建的是负载均衡（原应用型）；存量传统型实例可以继续使用，传统型教程也只对存量用户有意义。

**四层和七层监听器怎么选？**

TCP、UDP、TCP SSL 是四层，按端口转发；HTTP、HTTPS 是七层，能按域名和 URL 路径分发。业务是 HTTP/HTTPS 且需要按域名或路径分流，选七层；只需要端口转发，选四层。

**健康检查一直异常怎么办？**

先确认 CVM 上的服务端口正常监听，再检查安全组。关闭默认放通的场景，公网 CLB 要在 CVM 安全组放通 CLB 的 VIP；开启默认放通的场景，确认 CLB 安全组本身放通了业务端口。

**权重设为 0 会怎样？**

这台服务器不再接受新请求，但不会从后端列表里删除，适合下线前做过渡。

**绑定后端时为什么看不到我的 CVM？**

绑定弹窗只显示同地域、同 VPC、相同网络环境、未被隔离、未过期、带宽峰值不为 0 的 CVM。跨地域或跨 VPC 要用跨地域绑定 2.0。
